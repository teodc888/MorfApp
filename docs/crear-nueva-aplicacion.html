🚀 Crear Nueva Aplicación en MorfApp

Guía completa para desplegar nuevas instancias multi-tenant

📋 Visión General

MorfApp utiliza un modelo multi-tenant por subdominio. Esto significa que cada aplicación (como amadeo.morfapp.app o dev.morfapp.app) es una instancia completamente independiente en cuanto a la experiencia del usuario, pero comparte la misma base de datos backend.

🏗️ Arquitectura Multi-Tenant

  • Frontend (Next.js): Interpreta el subdominio y reescribe las rutas internamente
  • Backend (.NET): Diferencia tenants por TenantId extraído del JWT
  • Base de Datos (PostgreSQL): Una sola BD con aislamiento por TenantId
  • Cloudflare Tunnel: Proxy que dirige todos los subdomios al backend

Ejemplo: Cuando un usuario accede a dev.morfapp.app, la aplicación sabe que es el tenant dev y solo muestra datos donde TenantId = 'dev-tenant-uuid'.

✅ Requisitos Previos

  • ✓ Acceso al servidor (teo@192.168.0.55)
  • ✓ Acceso a Cloudflare DNS y Tunnel
  • ✓ Base de datos PostgreSQL activa y accesible
  • ✓ Frontend y Backend desplegados y funcionando
  • ✓ Herramientas: curl, psql, editor de texto

🔐 ¿Cómo Diferencia Entre Proyectos?

1️⃣ Frontend (Next.js Middleware)

El archivo front/src/proxy.ts intercepta cada request y reescribe las rutas según el subdominio:

Subdominio Ruta interna Componentes
amadeo.morfapp.app /store/amadeo/... Storefront público + Admin
dev.morfapp.app /store/dev/... Storefront público + Admin
admin.morfapp.app /admin/... Admin global
super.morfapp.app /superadmin/... Superadmin

2️⃣ Backend (.NET 9)

El JWT token incluye un claim tenant_id que identifica al tenant:

// En cada endpoint AdminController, se extrae: var tenantId = User.FindFirst("tenant_id")?.Value; // Luego se filtra la BD por este TenantId: var products = await context.Products .Where(p => p.TenantId == tenantId) .ToListAsync();
⚠️ CRÍTICO: Cada nuevo endpoint debe filtrar explícitamente por TenantId. No hay middleware global que lo haga. Si olvidas el filtro, un usuario podría ver datos de otros tenants.

3️⃣ Base de Datos (PostgreSQL)

Una sola BD compartida para todos los tenants. El aislamiento ocurre a nivel de aplicación:

-- Tabla example: CREATE TABLE products ( id UUID PRIMARY KEY, tenant_id UUID NOT NULL, -- ← Campo de aislamiento name VARCHAR NOT NULL, ... ); -- Índice para queries rápidas por tenant: CREATE INDEX idx_products_tenant_id ON products(tenant_id);

4️⃣ JWT Token

El token de autenticación contiene:

{ "sub": "user-uuid", "email": "admin@dev.morfapp.app", "is_superadmin": false, "tenant_id": "dev-tenant-uuid", "tenant_slug": "dev", "exp": 1234567890 }

📝 Paso a Paso: Crear Nueva Aplicación

Asumiendo que quieres crear dev.morfapp.app:

Paso 1: Crear el Tenant en la Base de Datos

Conectarte a PostgreSQL y crear el registro del tenant:

psql -h localhost -U postgres -d morfapp_db -- Generar un UUID para el tenant (ej: dev-tenant-uuid) INSERT INTO tenants ( id, slug, name, is_active ) VALUES ( 'dev-tenant-uuid', 'dev', 'Dev Store', true ); -- Crear configuración de branding INSERT INTO tenant_brandings ( id, tenant_id, logo_url, primary_color, secondary_color ) VALUES ( gen_random_uuid(), 'dev-tenant-uuid', 'https://...', '#667eea', '#764ba2' );

Nota: Guarda el tenant_id que acabas de crear.

Paso 2: Configurar DNS en Cloudflare

Agregar un registro DNS que apunte el subdominio al tunnel:

  1. Ve a Cloudflare Dashboard → DNS
  2. Agrega un nuevo registro CNAME:
    • Nombre: dev
    • Apunta a: 64358d35-f78d-426e-b221-3225bb277276.cfargotunnel.com (ID del tunnel)
    • Proxy status: Proxied (naranja)
  3. Guarda y espera propagación (usualmente segundos)

Paso 3: Configurar el Cloudflare Tunnel

Agregar la ruta del nuevo subdominio al archivo de configuración del tunnel:

sudo nano /etc/cloudflared/config.yml # Agregar antes de la línea final http_status:404: - hostname: dev.morfapp.app service: http://localhost:3200

Luego reinicia el servicio:

sudo systemctl restart cloudflared
✅ Verificación: curl -I https://dev.morfapp.app debe devolver HTTP 200

Paso 4: Crear Usuario Admin para el Tenant

El primer admin debe crearse directamente en la BD (no existe UI de signup aún):

INSERT INTO admin_users ( id, tenant_id, email, password_hash, is_active, created_at ) VALUES ( gen_random_uuid(), 'dev-tenant-uuid', 'admin@dev.morfapp.app', 'bcrypt-hash-here', -- Usa bcrypt true, now() );

Nota: Para generar el bcrypt hash, usa Node.js, Python, o una herramienta online de bcrypt.

Paso 5: Probar el Login

Accede a dev.morfapp.app/store/dev/admin e ingresa:

  • Email: admin@dev.morfapp.app
  • Contraseña: (la que creaste en bcrypt)

Si ves el panel de admin, ¡está todo correcto! ✅

Paso 6: Verificar Aislamiento de Datos

Crea un producto en dev.morfapp.app y verifica que NO aparece en amadeo.morfapp.app:

  1. Ve a dev.morfapp.app/store/dev/admin → Crear producto "Dev Product"
  2. Ve a amadeo.morfapp.app/store/amadeo/admin → Verifica que no lo ves
  3. Si el aislamiento funciona, ¡listo! ✅

✔️ Checklists

Antes de Crear

  • ☐ Decidiste el slug del tenant (ej: dev, store2, etc.)
  • ☐ Tienes acceso a PostgreSQL
  • ☐ Tienes acceso a Cloudflare DNS & Tunnel
  • ☐ Tienes acceso SSH al servidor

Después de Crear (Verificación)

  • ☐ curl -I https://[slug].morfapp.app devuelve 200 OK
  • ☐ El tenant existe en BD: SELECT * FROM tenants WHERE slug='[slug]';
  • ☐ El CNAME está en Cloudflare DNS (proxy ON)
  • ☐ El hostname está en /etc/cloudflared/config.yml
  • ☐ Puedes hacer login con el admin creado
  • ☐ Los datos del nuevo tenant no aparecen en otros tenants

🔧 Troubleshooting

❌ "503 Service Unavailable"

Causa: El frontend no está escuchando en localhost:3200

# Verifica que Next.js está corriendo: ps aux | grep next # O en el servidor: netstat -tulpn | grep 3200

❌ "404 Not Found"

Causa: El hostname no está en /etc/cloudflared/config.yml o el archivo no fue reloaded

# Verifica que la entrada existe: grep "dev.morfapp.app" /etc/cloudflared/config.yml # Reinicia cloudflared: sudo systemctl restart cloudflared # Verifica logs: sudo journalctl -u cloudflared -f

❌ "DNS NXDOMAIN"

Causa: El CNAME no está configurado en Cloudflare o aún no propagó

# Espera 1-2 minutos y verifica: nslookup dev.morfapp.app # O en el servidor: dig dev.morfapp.app

❌ Usuario ve datos de otro tenant

Causa: El endpoint backend no filtra por TenantId

// En AdminController, SIEMPRE agrega: var tenantId = User.FindFirst("tenant_id")?.Value; var data = await context.SomeTable .Where(x => x.TenantId == tenantId) // ← OBLIGATORIO .ToListAsync();

🏗️ Detalles Técnicos Adicionales

Flujo de Autenticación

1. Usuario ingresa email/password en dev.morfapp.app 2. POST /api/auth/login con credenciales 3. Backend verifica en BD (admin_users WHERE email = X AND tenant_id = Y) 4. Si OK, retorna JWT con claims: - sub: user-id - email: user@dev.morfapp.app - tenant_id: a1b2c3d4-... - tenant_slug: "dev" 5. Frontend guarda token en localStorage 6. Siguientes requests envían Authorization: Bearer [token] 7. Backend valida token y extrae tenant_id de los claims

Token Refresh

Los tokens access son válidos por 15 minutos. Cuando expiran:

  1. Frontend detecta 401 Unauthorized
  2. Llama a POST /api/auth/refresh con el refresh_token
  3. Backend valida que el refresh_token esté en la BD y no esté revoked
  4. Genera nuevo access_token
  5. Retorna nuevo token al frontend

Índices Recomendados en la BD

-- Para queries rápidas por tenant: CREATE INDEX idx_products_tenant_id ON products(tenant_id); CREATE INDEX idx_categories_tenant_id ON categories(tenant_id); CREATE INDEX idx_admin_users_tenant_id ON admin_users(tenant_id); CREATE INDEX idx_admin_users_email_tenant ON admin_users(email, tenant_id); -- Para login: CREATE INDEX idx_admin_users_email ON admin_users(email);

⚙️ Variables de Entorno

Frontend (front/.env.local)

Estas variables son globales (no por tenant):

# URL pública del API NEXT_PUBLIC_API_URL=https://api.morfapp.app # URL interna para SSR (evita round-trip de red) NEXT_INTERNAL_API_URL=http://localhost:5200 # Dominio raíz (debe ser igual en todos los tenants) NEXT_PUBLIC_ROOT_DOMAIN=morfapp.app

Backend (back/appsettings.json o env vars)

{ "ConnectionStrings": { "DefaultConnection": "Host=192.168.0.55;Database=morfapp_db;Username=postgres;Password=..." }, "Jwt": { "Secret": "your-secret-key-min-32-chars-in-prod", "Issuer": "morfapp", "Audience": "morfapp-users", "ExpirationMinutes": 15 }, "App": { "RootDomain": "morfapp.app", "RefreshTokenExpirationDays": 7 } }
⚠️ Importante: El RootDomain es global. Si cambias de morfapp.app a otro dominio, afecta TODOS los tenants. Actualiza simultáneamente en frontend y backend.

📌 Resumen Final

🗄️ Base de Datos

Una sola BD PostgreSQL compartida. Aislamiento por TenantId en aplicación.

🌐 Frontend

Middleware Next.js reescribe subdominio → path. Comparten código, no datos.

🔐 JWT Token

Claim tenant_id identifica al tenant. Backend extrae y filtra por él.

🚀 Cloudflare

Un tunnel con múltiples hostnames. Cada subdominio → servicio local.

✅ Crear nueva aplicación es simple:

  1. Crear Tenant en BD
  2. Agregar CNAME en Cloudflare
  3. Agregar hostname en Cloudflare Tunnel config
  4. Crear usuario admin
  5. ¡Listo! Ya tienes una nueva instancia aislada
