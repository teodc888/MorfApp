MorfApp Agents

Flujo de Trabajo con Agentes

Sistema de orquestadores jerárquico para desarrollar MorfApp de forma consistente y controlada

1 ¿Qué es este sistema?

En lugar de escribir código directamente, usamos un sistema de agentes especializados que trabajan en capas. Primero analizan el código existente y te muestran un plan. Vos aprobás el plan antes de que se toque una sola línea de código.

✅ La regla clave: Los orquestadores solo analizan y planifican — nunca escriben código. Los agentes de implementación solo ejecutan lo que el plan aprobado dice.

└── 🧠 morf-master ← analiza y delega
├── ⚙️ morf-back-orchestrator ← genera plan → espera OK

├── 🎨 morf-front-orchestrator ← genera plan → espera OK
├── morf-front-page → páginas admin panel
├── morf-front-component → componentes UI
└── morf-front-api → admin-api.ts + tipos
├── 👑 morf-superadmin-orchestrator ← genera plan → espera OK
├── morf-superadmin-page → páginas superadmin
└── morf-superadmin-api → superadmin-api.ts
└── 🚀 morf-devops-orchestrator ← genera plan → espera OK
├── morf-devops-pipeline → Jenkinsfiles
└── morf-devops-config → variables + config server
■ Orquestadores (solo analizan y planifican)
■ Agentes de implementación (escriben código)

3 Cómo usarlo — paso a paso

1

Elegí el modelo según la complejidad

Antes de arrancar, elegí qué tan potente querés que sea el agente. Todos los agentes heredan este modelo automáticamente.

# Escribe esto en el chat de Claude Code /model haiku # rápido y barato — para cosas simples /model sonnet # balance calidad/velocidad — uso diario /model opusplan # máxima calidad — para cosas complejas
2

Escribí tu requerimiento con /morf

Describí en lenguaje natural lo que necesitás. No hace falta saber qué archivos tocar — el sistema lo descubre solo.

# Ejemplos de uso /morf quiero agregar un campo 'descripción' al tenant /morf crear endpoint para pausar/activar un producto /morf agregar filtro por fecha en la vista de pedidos /morf el superadmin necesita ver los logs de actividad
3

Revisá el plan que te genera el orquestador

El sistema lee el código real del proyecto, analiza el impacto y te genera un plan con archivos específicos y tareas en orden. Todavía no se tocó nada.

4

Aprobás o pedís cambios

El orquestador te pregunta explícitamente si aprobás. Podés decir S, pedir ajustes, o cancelar. Solo con tu OK se ejecuta algo.

5

Los agentes ejecutan el código

Con el plan aprobado, los agentes especializados escriben el código en el orden correcto (entity → migration → controller → frontend).

5 Elegir el modelo correcto

⚡

Haiku

/model haiku

Tareas simples y repetitivas. Más rápido, más barato. Ideal para pequeños ajustes de texto, typos, renombrar cosas.

⚖️

Sonnet

/model sonnet

Uso diario recomendado. Buen balance entre calidad y velocidad. Para features completas, nuevos endpoints, páginas del admin.

🧠

Opus (plan mode)

/model opusplan

Para decisiones de arquitectura, refactors grandes, o cuando algo es complejo y querés la mejor calidad posible.

💡 Cuando cambiás el modelo con /model, todos los agentes heredan ese modelo automáticamente. No hay que configurar nada más.

6 Qué hace cada orquestador

morf-back-orchestrator

Gestiona el backend .NET 9. Trabaja en entidades, migraciones EF Core, endpoints REST y tests xUnit.

No escribe código

morf-front-orchestrator

Gestiona el admin panel Next.js. Páginas, componentes UI, tipos TypeScript y llamadas a la API.

No escribe código

morf-superadmin-orchestrator

Gestiona el SuperAdmin standalone (app separada). Lista de tenants, creación, edición y configuración global.

No escribe código

morf-devops-orchestrator

Gestiona Jenkinsfiles, scripts de deployment y configuraciones del servidor en producción y PRE.

No escribe código

7 Tips importantes

🔀 El sistema detecta automáticamente qué proyectos afecta

No hace falta decirle "esto es del backend". Describí el requerimiento en lenguaje normal y el morf-master decide qué orquestadores invocar.

✏️ Podés pedir cambios al plan antes de aprobar

Si el orquestador te muestra un plan y algo no te convence, decile exactamente qué cambiar. El plan se ajusta antes de ejecutarse.

🌿 Rama development para el día a día

Estamos trabajando sobre la rama development. Cuando algo está probado en PRE y listo, se mergea a master que dispara el deploy a PROD.

⚠️ Para cambios en el pipeline de PROD: el orquestador te va a pedir una confirmación extra antes de tocar Jenkinsfile.prod. Siempre revisá dos veces estos cambios.
